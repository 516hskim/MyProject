# 기술 구현과 가능성

## 결론

시설이 주차면별 상태와 층별 실내 지도 데이터를 제공하고, 차량 위치를 해당 지도에 정합할 수 있는 허가된 인터페이스가 있다면 면 단위 빈자리 안내를 구현할 수 있습니다. 첫 번째 조건은 사용자가 제시한 가정으로 충족됩니다. 두 번째 조건인 앱의 INS/오도메트리 접근 권한은 Pleos SDK 공개 문서만으로 확인되지 않으므로 별도로 검증해야 합니다.

## 필요한 시설 데이터

1. 층별 주차면 상태와 갱신 시각
2. 실내 좌표계와 주행 통로 그래프
3. 램프, 일방통행, 진입 금지, 출입구, 엘리베이터 노드
4. 입주민/방문객/전기차/장애인/차량 높이 등 이용 자격
5. 실시간 변경 이벤트 또는 짧은 주기의 조회 API

좌표는 단지별 로컬 좌표계로 고정하고, 주차장 입구와 차량 지도 기준점을 동일한 좌표계에 매핑합니다. 층 이름은 `B2` 같은 화면 표기와 API의 고유 `floorId`를 분리합니다.

## 차량 위치 추정

### 허가된 INS/오도메트리 접근이 가능한 경우

1. 주차장 입구의 지도 기준 노드나 게이트 이벤트로 초기 위치를 설정합니다.
2. INS의 상대 이동량과 차량 진행 방향을 누적해 위치 후보를 계산합니다.
3. 후보 위치를 주차장 통로 그래프의 연결된 도로에 맞춥니다. 통로에서 벗어난 위치는 낮은 가중치를 주고, 일방통행과 램프 연결을 반영합니다.
4. 층 전환은 고도 변화만으로 판단하지 않고 램프 경로, 게이트 이벤트, 층 진입 노드를 함께 사용합니다.
5. 위치 신뢰도가 기준 아래로 내려가면 사용자에게 층/구역 확인을 요청하고, 안내를 주차면 단위에서 구역 단위로 낮춥니다.

INS 오차는 주행 거리에 따라 누적되므로 주차장 지도 제약, 게이트/기준점 재보정, 정차 상태를 이용한 재설정이 필요합니다. 지도와 INS가 있다고 해서 실내 위치가 자동으로 항상 정확해지는 것은 아닙니다.

### 원시 INS가 앱에 공개되지 않는 경우

공개 FusedLocation 데이터로 확인되는 위치 필드는 위도·경도·고도·진행 방향·신뢰도·시각입니다. 이 정보만으로 층·주차면 수준 위치를 보장한다고 간주하지 않습니다. 대안은 다음과 같습니다.

- Pleos/차량 사업자에게 승인된 실내 위치 또는 차량 위치 API 제공을 요청
- 주차장 입구·층별 게이트 이벤트를 기준으로 위치를 재보정
- 사용자가 층/구역을 직접 선택하고, 앱은 해당 구역의 후보 면만 안내
- 시연 단계에서는 정해진 위치 트레이스를 재생해 알고리즘 흐름을 보여 줌

## 빈자리 선택과 경로 계산

필수 이용 조건을 먼저 적용합니다. 예: 방문객 허용, 전기차 충전 가능, 차량 높이 제한 충족. 통과한 후보 중 다음 비용을 최소화합니다.

```text
cost = 0.40 × 정규화한 차량 주행 시간
     + 0.25 × 목적 동까지 보행 시간
     + 0.15 × 회전/복잡도 비용
     + 0.12 × 점유 데이터 노후도 비용
     + 0.08 × 위치 불확실성 비용
```

가중치는 초기 제품 가설입니다. 입주민/방문객 유형, 목적 동, 사용자의 걷기 선호와 파일럿 결과로 조정합니다. 점유 상태가 `UNKNOWN`, `RESERVED`, `RESTRICTED`이면 추천 후보로 표시하지 않습니다.

선택한 주차면이 다른 차량에 의해 점유되면 API의 최신 이벤트를 반영해 대체 경로를 계산합니다. 시설 시스템이 예약/홀드 API를 제공하지 않는 한 앱은 면을 예약했다고 표현하지 않습니다.

## Pleos Connect 연동안

| 영역 | 연동 | 처리 원칙 |
|---|---|---|
| 차량 내 경로 안내 | NaviHelper | 주차장 진입점까지 목적지 경로를 요청하고, 앱의 내부 경로와 역할을 구분 |
| 차량 상태 | Vehicle State | 필요한 상태만 권한 승인 후 사용하고 `checkXXXCapabilities`로 차종별 지원 확인 |
| 차량 위치 | FusedLocation 또는 별도 승인 API | 지원 여부를 런타임 확인. 공개 필드만으로 INS/층별 측위를 단정하지 않음 |
| 주차 데이터 | 단지 주차 운영 API | 사용자 자격 확인, 갱신 시각 검사, 네트워크 단절 시 오래된 데이터 표시 |
| 실내 지도 | 운영사 지도/그래프 | 면·통로·램프·보행 출입구를 하나의 지도 버전으로 관리 |

현재 공식 프로젝트 SDK 접근 문서는 FusedLocation을 `Not Available Yet`, Vehicle State와 NaviHelper를 `Ready to Use`로 안내합니다. 실제 개발에서는 Pleos Playground의 프로젝트별 상태와 차량별 API 지원을 다시 확인합니다.

## 시제품과 개발 단계

1. **제출 시연:** 현재 HTML 시제품과 가상 주차 데이터로 이용 흐름을 설명합니다.
2. **에뮬레이터 MVP:** Kotlin 앱, 샘플 주차 데이터, 고정 위치 트레이스, 층/면 지도, 주차 저장/귀환을 구현합니다.
3. **단지 파일럿:** 주차 운영 API 1곳과 지도 1종을 연동하고, 입주민/방문객 권한 및 상태 갱신을 검증합니다.
4. **차량 측위 검증:** 승인된 INS/위치 API와 실제 Pleos 차량에서 정합 오차, 층 전환, 데이터 단절 동작을 측정합니다.
5. **확대:** 단지별 지도 어댑터와 상태 API 차이를 표준 스키마로 변환합니다.

## 개인정보와 안전

- 전체 입주민에게 다른 차량 번호나 운전자 위치를 노출하지 않습니다.
- 위치 기록은 주차 세션 동안만 사용하고, 목적 달성 후 보존 기간을 최소화합니다.
- 방문자에게는 초대된 시설/구역만 보여 줍니다.
- 주행 중 화면은 다음 안내와 큰 버튼 위주로 제한하고, 세부 검색·설정은 정차 후 제공합니다.
- 데이터 지연, 위치 불확실, 이용 제한을 숨기지 않고 사용자가 대체 구역을 선택할 수 있게 합니다.
